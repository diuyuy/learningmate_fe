## 프로젝트 설명

경제 용어 학습을 돕는 AI 기반 학습 플랫폼입니다. 매일 새로운 경제 용어와 관련 학습 컨텐츠(동영상, AI 생성 아티클, 퀴즈)를 제공하여 경제 지식을 체계적으로 쌓을 수 있도록 돕습니다.

**개발 기간**: 2025.8월 ~ 2025.11월

**팀 구성**: 3명

## 주요 개선 사항

### 리프레시 토큰 재발급 시 중복 요청 방지

**문제점:**

처음에는 단순하게 axios 인스턴스에 액세스 토큰 만료 시 리프레시 토큰을 재발급하는 인터셉터를 추가했습니다. 하지만 한 페이지에서 여러 API 요청이 동시에 발생할 경우, 각 요청마다 독립적으로 401 에러를 받아 토큰 갱신 요청을 중복으로 보내는 문제가 발생했습니다.

**해결 방법:**

다음과 같은 방법을 사용하여 문제를 해결했습니다:

- `isRefreshing`: 현재 토큰 갱신 진행 중인지 확인하는 플래그
- `failedQueue`: 토큰 갱신 중에 실패한 요청들을 저장하는 큐
- `_retry`: 요청 객체에 재시도 여부를 표시하는 속성

토큰 갱신 요청이 이미 진행 중이면 새로운 실패 요청들을 `failedQueue`에 저장하여 대기시킵니다. 토큰이 성공적으로 갱신되면 `processQueue` 함수로 대기 중인 모든 요청을 순차적으로 재실행합니다. 토큰 갱신 실패 시 `processQueue` 함수로 기존 요청을 모두 에러로 반환합니다.

**결과:**

API 동시 요청 시 발생하는 토큰 갱신 레이스 컨디션을 해결하여, 불필요한 서버 부하를 줄이고 인증 로직의 안정성을 확보했습니다. 단 한 번의 갱신 요청만 처리되도록 보장합니다.

### 처음 화면 접속 시 리프레시 토큰이 있어도 메인 화면으로 못 가는 오류

**문제점:**

서비스를 기획할 때 사용자가 사이트 접속 시 로그인이 되어 있는 상태면 바로 메인 페이지로 가고, 아닐 시 랜딩 페이지로 가도록 구상했습니다. 그런데 액세스 토큰이 있을 때는 문제없이 메인 페이지로 잘 접속됐지만, 액세스 토큰은 없고 리프레시 토큰만 있을 시 메인 페이지가 아닌 랜딩 페이지로 이동하는 문제가 발생했습니다.

**문제 원인 및 해결 방법:**

**Axios** 인스턴스에 인터셉터를 등록하는 함수를 `SessionProvider`의 `useEffect()` 내부에서 호출했었습니다. 그런데 `SessionProvider`가 `RouterProvider`의 부모 컴포넌트인 관계로 `RouterProvider`의 `useEffect()`가 `SessionProvider`의 `useEffect()`보다 먼저 실행되어 인터셉터가 등록되지 않은 상태에서 리프레시 토큰 갱신이 시도되어 실패했습니다.

`SessionProvider` 내에서 인터셉터를 `useLayoutEffect()`로 등록하여 `RouterProvider`가 마운트되는 것보다 인터셉터가 먼저 등록되도록 수정함으로써 문제를 해결했습니다.
